# Deploying EkBill on the tariff-order VM

> **Moving to its own VM:** EkBill is moving off the shared tariff-order VM to a VM of its own
> (`ekbill`). Follow [own-vm.md](own-vm.md); the everyday commands below work the same there.

EkBill runs as a Docker Compose stack on the existing `tariff-order` VM (project
`tariff-order-parsing`, zone `asia-south2-b`), next to the tariff product and never touching it.

```
Internet ──443──> caddy (HTTPS, shared password) ──> app (Next.js) ──> db (Postgres 16 + pgvector)
                                                         │
                                                         ├──> docling (OCR for photos and scans, inside the stack only)
                                                         └──> OpenAI (voice, Poocho answers, contract reading; optional)
```

| Piece | Where | Notes |
| --- | --- | --- |
| `app` | `127.0.0.1:8080` | Built from this repo's `Dockerfile`; applies migrations on start |
| `db` | `127.0.0.1:5441` | `pgvector/pgvector:pg16`, volume `ekbill_pgdata` |
| `docling` | internal `docling:5001` | `quay.io/docling-project/docling-serve-cpu:v1.35.0`, capped at 2 CPUs and 6 GB |
| `caddy` | `0.0.0.0:80,443` | Automatic Let's Encrypt certificate; basic-auth gate while sign-in is off |
| Secrets | Secret Manager | `ekbill-db-password`, `ekbill-gate-password` (generated by Terraform), `ekbill-openai-api-key` (you type it) |
| Backups | `gs://tariff-order-parsing-ekbill-backups/pg/` | Nightly `pg_dump` at 02:30 IST, kept 30 days |
| Terraform | `infra/gcp`, state `gs://tarifforderstudio_tfstate/ekbill/dev` | Secrets, bucket, static IP, firewall `ekbill-allow-web` |

Ports the product uses (3000, 5432, 5433, 8000) are not touched. Everything EkBill creates is
named `ekbill-*` and labelled `app=ekbill`.

## First time

The quickest path is to paste [prompts/ekbill-on-vm.md](prompts/ekbill-on-vm.md) into Claude
Code on the VM. It does everything except step 2, which you run yourself in a second SSH window
because it waits for typed answers. By hand, it's the following steps.

1. **Get the code onto the VM** with its own deploy key (never the tariff key):

   ```bash
   ssh-keygen -t ed25519 -C "ekbill-vm" -f ~/.ssh/id_ed25519_ekbill -N ""
   cat ~/.ssh/id_ed25519_ekbill.pub   # add at github.com/Ergplan/easybills > Settings > Deploy keys (read-only)
   cat >> ~/.ssh/config <<'EOF'
   Host github-ekbill
     HostName github.com
     User git
     IdentityFile ~/.ssh/id_ed25519_ekbill
     IdentitiesOnly yes
   EOF
   git clone -b claude/admiring-wright-5w8x4g git@github-ekbill:Ergplan/easybills.git ~/easybills
   ```

2. **Run the setup**, which is safe to run again:

   ```bash
   cd ~/easybills && deploy/vm/setup.sh
   ```

   It checks disk and ports, then applies Terraform (its own state prefix). Next it adds the
   `ekbill-web` network tag to the VM so the firewall rule applies, and asks for the OpenAI key at
   a hidden prompt (Enter skips). It then installs the nightly backup in cron and runs
   `deploy/vm/up.sh`.

3. **Open the address it prints.** Without a domain it is `https://<ip-with-dashes>.sslip.io`,
   which resolves to the VM with no DNS setup. The browser asks for a user and password: the
   user is `ekbill` and the password is:

   ```bash
   gcloud secrets versions access latest --secret=ekbill-gate-password
   ```

The first HTTPS request can take about 30 seconds while Caddy gets the certificate. The first
photo sent to Docling is slow while its models warm up.

## Using a real name (recommended)

Add a DNS A record, e.g. `ekbill.aayuda.energy`, pointing at the VM's IP (`terraform -chdir=infra/gcp output external_ip`). Then:

```bash
echo ekbill.aayuda.energy > ~/easybills/deploy/vm/domain
deploy/vm/up.sh
```

## Everyday commands (on the VM)

| What | Command |
| --- | --- |
| Update to the latest code | `cd ~/easybills && git pull && deploy/vm/up.sh` |
| Status | `docker compose -p ekbill ps` and `curl -s localhost:8080/api/health` |
| Logs | `docker compose -p ekbill logs -f app` (or `docling`, `caddy`, `db`) |
| Stop | `docker compose -p ekbill -f deploy/docker-compose.yml down` (keeps the data volume) |
| Add or change the OpenAI key | `deploy/vm/set-openai-key.sh` |
| Restart without rebuilding (low disk, or only the address changed) | `EKBILL_NO_BUILD=1 deploy/vm/up.sh` |
| Free EkBill's own old images (never the product's) | `deploy/vm/free-space.sh` |
| Restore the newest backup | `deploy/vm/restore.sh latest --replace && EKBILL_NO_BUILD=1 deploy/vm/up.sh` |
| Back up now | `deploy/vm/backup.sh` |
| psql | `docker compose -p ekbill exec db psql -U ekbill` |
| From your laptop without the public address | `gcloud compute ssh tariff-order --zone asia-south2-b --project tariff-order-parsing -- -N -L 8080:localhost:8080`, then http://localhost:8080 |

Never run `docker system prune` or `docker volume prune` on this VM: the product's build cache
and volumes live there too.

## When the VM's IP changes

The sslip.io name is built from the IP, so a new IP (something replaced the VM's network
interface, e.g. an apply of the product's Terraform) makes the old link time out while the app
keeps running. Reserve the new IP and point Caddy at it, without a build:

```bash
cd ~/easybills && git pull && EKBILL_NO_BUILD=1 deploy/vm/setup.sh
```

The plan releases the old reserved address and reserves the current one; nothing else should be
in it. A real domain name (below) keeps the link the same; only its A record changes.

## /api/health

Open without the gate password, and has no secrets in it:

```json
{"ok":true,"signIn":"switched off - OPEN ACCESS, ...","database":"ok","schema":"0002_search.sql",
 "pdfs":"ok","docling":"ok","voice":"configured (gpt-realtime)"}
```

`database` failing comes with a `hint`. `docling: FAILED` means photos will be refused politely
until it is back: `docker compose -p ekbill logs docling`. `voice: off` means no OpenAI key.

## Backups and restoring one

`deploy/vm/backup.sh` streams `pg_dump -Fc` straight to the bucket. To restore, onto a fresh
database first to check it:

```bash
gcloud storage ls gs://tariff-order-parsing-ekbill-backups/pg/ | tail -3
gcloud storage cp gs://tariff-order-parsing-ekbill-backups/pg/ekbill-YYYYMMDD-HHMMSS.dump /tmp/ekbill.dump
docker compose -p ekbill exec -T db createdb -U ekbill ekbill_restore
docker compose -p ekbill exec -T db pg_restore -U ekbill -d ekbill_restore --no-owner < /tmp/ekbill.dump
docker compose -p ekbill exec db psql -U ekbill -d ekbill_restore -c "select count(*) from invoices"
```

To make the restore live: stop `app`, drop and recreate `ekbill` from the dump the same way, then
run `deploy/vm/up.sh`.

## Before real books go in

Sign-in is switched off (`AUTH_BYPASS=true`). Everyone who gets past the gate password is the
same test owner and can see and change everything. That is deliberate while the app is being
shaped, and it has to end before a real business's bills go in:

1. Firebase project `ekbill-1918b`: enable the Phone sign-in provider and add the domain above
   to Authentication > Settings > Authorized domains.
2. Session cookies need the Firebase Admin credentials of `ekbill-1918b` on the VM. Use workload
   identity federation or grant the VM's service account access; don't download a
   service-account key.
3. Set `AUTH_BYPASS=false`, e.g. `AUTH_BYPASS=false deploy/vm/up.sh`, and decide whether the
   gate password stays.

## What is not automated

- DNS for a real domain (one A record).
- The Docling image tag: `v1.35.0` matches the docling-serve release on PyPI. If the pull fails,
  `DOCLING_IMAGE=quay.io/docling-project/docling-serve-cpu:latest deploy/vm/up.sh`.
- Monitoring and alerts beyond `/api/health` and `restart: unless-stopped`.
